# Phased delivery plan — Kirana Voice Billing

Each phase ends with lint, type-check, unit, migration, integration, build and (where a
critical workflow is complete) end-to-end checks. Results are recorded in
[`implementation-status.md`](implementation-status.md).

| Phase                      | Scope                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Exit criteria                                                                                                                                 |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. Foundation**          | npm-workspaces monorepo (`apps/api`, `apps/web`, `packages/shared`); TypeScript, ESLint, Prettier; env validation; structured redacted logging; Express app under `/api/v1` with helmet, body-size limits, rate limits, request timeouts, safe errors, health check; Prisma + PostgreSQL schema for users, stores, memberships, sessions, audit log; email/password auth with DB-backed sessions; tenant-scoped store endpoints with role checks and audit records; React + Vite shell with i18next (en/hi/te/ur), Urdu RTL, separate UI / speech / receipt language settings | Cross-tenant tests pass; migrations apply on a clean DB; both builds succeed; e2e smoke (register → create store → switch to Urdu RTL) passes |
| **2. Catalog & inventory** | Products with multilingual names + aliases (for later voice matching), units (kg/g/l/ml/piece/pack), `NUMERIC` prices and tax rates, stock balances derived from an append-only `InventoryMovement` ledger, stock adjustments with reasons, CSV import                                                                                                                                                                                                                                                                                                                        | Tenant isolation tests for every product/stock route; decimal-arithmetic unit tests                                                           |
| **3. Manual billing**      | Draft cart → server-priced quote → finalize: sale, sale items, payments and inventory movements in one transaction; `Idempotency-Key` on finalize; cancellations / returns as separate records; explicit rounding (line → tax → total, half-up to paise)                                                                                                                                                                                                                                                                                                                      | Concurrency + duplicate-submit tests; e2e manual sale                                                                                         |
| **4. Receipts & reports**  | Printable receipt in the store's receipt language (independent of UI language), daily sales summary, low-stock report, audit log viewer                                                                                                                                                                                                                                                                                                                                                                                                                                       | Snapshot tests per language incl. Urdu RTL                                                                                                    |
| **5. Voice billing**       | `SpeechProvider` and `LlmProvider` interfaces + env-selected implementations; provider/model/locale compatibility check; schema-validated LLM extraction (name, qty, unit only — never prices); catalog matching scoped to tenant; clarification prompts for ambiguity; mandatory confirm step before finalizing (reuses Phase 3 finalize); manual fallback always available                                                                                                                                                                                                  | Fixture-based parser tests incl. adversarial transcripts; no key in client bundle                                                             |
| **6. Deployment**          | Docker Compose (api, web/static, PostgreSQL with volume, Caddy reverse proxy + HTTPS) after VPS compatibility check; least-privilege DB role; `prisma migrate deploy` as explicit step after verified `pg_dump` backup; backup/restore runbook                                                                                                                                                                                                                                                                                                                                | Staging deploy observed healthy; restore drill documented                                                                                     |
| **7. Hardening**           | Session management UI, password reset, invite staff to store, observability, load test of finalize path, accessibility pass                                                                                                                                                                                                                                                                                                                                                                                                                                                   | —                                                                                                                                             |
